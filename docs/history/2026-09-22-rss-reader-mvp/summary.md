# 訪談摘要與結論

日期：2026-09-22。主題：Obsidian Feedly-like RSS reader MVP。

## 使用者目標

在 Obsidian 管理 RSS 訂閱、以 Feedly-like 快捷鍵閱讀，並將想保留的文章保存成 vault Markdown。第一步交付可建置骨架、README、SPEC 與可供 PM 派工的精簡任務包；依難度提供模型建議，由使用者確認工具／模型後再啟動 workers。

## 訪談收斂

- Q1–5：桌面版、獨立 reader；YAML 權威清單、TOML 交換；保存 feed 內容，不抓網頁全文。
- Q6–12：訂閱、已讀、筆記留 vault，快取本機；不負責 vault 同步。接受側欄＋雙欄 reader、j/k 等操作、30 分鐘更新及 500 篇快取。保存不覆寫人工編輯。
- Q13–19：已讀按來源 JSON；已讀檢視只看快取。**分類最終改為單層且多歸屬，覆蓋先前巢狀需求。** 允許 YAML 外部編輯但錯誤時暫停回寫。保存追蹤不可拖慢效能。
- Q20–26：截止時間壓縮已讀，加上個別已讀及未讀例外；全已讀涵蓋後補舊文。未分類保留來源，首次抓取全未讀，僅直接 URL RSS/Atom。目標 200 來源。
- Q27–32：例外跨重啟保留；來源內穩定識別，更新不轉未讀；圖片不下載，禁止腳本／iframe；無正文仍保存；標題搜尋；reader 分頁存在時持續更新。

完整最終行為見根目錄 SPEC.md；此摘要保留「為什麼」與被取代的決策，不作第二份規格。

## 本次實作預設（不新增確認關卡）

- YAML 匯出按使用者最初要求納入，不因末輪未單獨回答而擱置。
- 使用 TypeScript、esbuild、Obsidian API；先不引入 UI framework、SQLite、服務容器。
- vault 可見資料預設放 `Feed Reader/`；快取建議 IndexedDB，確保不是誤放進會同步的 plugin 目錄。
- 已保存入口從筆記索引提供，快取淘汰後仍可開筆記；ID/time 邊界等實作細節列於 SPEC。
- 尚未執行任何功能 worker，沒有確定使用者要用的工具或模型；以下計畫是可審閱派工方案。

## 刻意延後

手機、Feedly 整合、登入來源、全文擷取、附件離線化、tags、巢狀分類、全文搜尋、跨裝置同步衝突、完整歷史文章庫。避免先做通用 framework、額外契約審批文件或大量 stub tests。
